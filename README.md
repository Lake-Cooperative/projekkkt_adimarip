# Реестр оповещений «АДИМАРИП»

Веб-приложение для учёта электронных оповещений для служащих: адресаты, статусы, история изменений, уведомления, обращения и метаданные сопроводительных документов.

> **Статус проекта: этап документации.** В репозитории пока есть только требования. Кода, `docker-compose.yml` и тестовых данных ещё нет, поэтому раздел «Запуск» описывает целевое поведение из требований, а не работающую команду. Ход работ — в [ROADMAP.md](ROADMAP.md).

Проект **учебный и демонстрационный**. Он работает с тестовыми данными, реальные SMS и e-mail не отправляются, файлы документов не загружаются (хранятся только метаданные).

## Возможности

- Ведение адресатов (ФИО, дата рождения, контакты, адрес) с проверкой уникальности идентификатора.
- Создание оповещений и просмотр реестра с поиском, фильтрами по статусу и подразделению и постраничным выводом.
- Карточка оповещения: адресат, подразделение, сроки, текущий статус, история статусов, уведомления, обращения, документы.
- Смена статуса с записью в историю и журнал аудита.
- Демонстрационная регистрация уведомлений (статус `Delivered`) и обращений (статус `Submitted`).
- Метаданные документов: имя, MIME type, URI или идентификатор хранилища.
- Ролевой доступ по JWT; учётные записи создаёт только инженер автоматизации.

## Роли

| Должность | Роль | Что может |
|---|---|---|
| Секретарь | `Operator` | Читать и изменять данные |
| Управитель | `Manager` | То же, плюс просмотр истории и аудита |
| Служащий | `Observer` | Читать данные и добавлять сведения о документах |
| Инженер автоматизации | `Automation Engineer` | Создавать учётные записи, запускать систему и проверять её работу |

Подробная матрица доступа по endpoint — в [system-requirements.md](system-requirements.md#4-роли-и-матрица-доступа).

## Запуск (целевое поведение)

Требования предполагают запуск всей системы одной командой:

```bash
docker compose up --build
```

После запуска должны быть доступны:

| Компонент | Адрес |
|---|---|
| UI | http://localhost:8080 |
| API | http://localhost:8081 |
| Swagger | http://localhost:8081/swagger |
| Проверка работоспособности | `GET http://localhost:8081/api/health` (без авторизации, ответ `status: ok`) |

Логины и пароли тестовых пользователей будут добавлены сюда, когда появится начальное заполнение БД.

## API

Все endpoint, кроме входа и `/api/health`, требуют заголовок `Authorization: Bearer <JWT>`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка работоспособности |
| `GET` | `/api/recipients?search=` | Поиск адресатов |
| `POST` | `/api/recipients` | Создание адресата |
| `GET` | `/api/offices` | Список подразделений |
| `GET` | `/api/notices` | Реестр: фильтры `status`, `officeId`, `search`, пагинация (`pageSize` 1–100) |
| `GET` | `/api/notices/{id}` | Карточка оповещения |
| `POST` | `/api/notices` | Создание оповещения |
| `PATCH` | `/api/notices/{id}/status` | Смена статуса |
| `POST` | `/api/notices/{id}/notifications` | Демонстрационное уведомление |
| `POST` | `/api/notices/{id}/appeals` | Регистрация обращения |

Endpoint входа, создания учётных записей и добавления документа в исходных требованиях не описаны; их предстоит определить (см. [открытые вопросы](system-requirements.md#10-открытые-вопросы-и-расхождения-в-источниках)).

Коды ошибок: `400` некорректные данные, `401` нет или истёк JWT, `403` недостаточно прав, `404` не найдено, `409` конфликт (дубликат номера, повтор текущего статуса).
