## Запуск

1. Скачайте исходный репозиторий, проверьте, что `git rev-parse HEAD` равен базовому SHA.
2. Примените патчи по инструкции внутри ZIP (`APPLY_INSTRUCTIONS.md`).
3. В `.env` установите новые, случайные значения `POSTGRES_PASSWORD`, `JWT_SECRET` (не короче 32 байт), `DEMO_PASSWORD` (не короче 10 символов).
4. Выполните `docker compose -f docker_compose.yml up --build`.
5. Откройте интерфейс http://localhost:8080, API http://localhost:8081, Swagger http://localhost:8081/swagger.
6. Демонстрационные аккаунты (при `DEMO_ENABLED=true`): `operator`, `manager`, `observer`, `engineer`; пароль из `DEMO_PASSWORD`.
7. После запуска проверьте `python3 tests/api_acceptance.py` и SQL-скрипт `tests/sql/schema-verification.sql`.

**Важно:** миграции запускаются автоматически при старте сервиса. Для первой проверки используйте пустую тестовую БД. Не выполняйте `docker compose down -v` над БД с важными данными. Таблица `AppUsers` создаётся idempotent SQL на этапе инициализации, прочая предметная модель — EF Core-миграциями.

## Ограничения

- Отправка E-mail, SMS, MAX, «Госуслуг» не интегрирована: только моделирование доставки.
- Госуслуги/MAX как провайдеры входа не реализованы; вход осуществляется по JWT/локальному паролю.
- Документы не загружаются на сервер, сохраняются только ссылки и метаданные.
- Объект `RecipientArchive` хранит причину списания, но не удаляет существующие оповещения.
- Текущая модель SQL-миграций содержит исходный неполный snapshot; перед дальнейшими изменениями модели требуется сгенерировать актуальный EF Core snapshot.
- Backend не скомпилирован в текущем окружении, так как здесь нет .NET SDK и Docker. Серия требует обязательной сборки и интеграционных тестов на машине команды перед принятием в `main`.
- Права и хранение демо-секретов не предназначены для производства. Нельзя обрабатывать реальные персональные данные.

## Сценарий показа

1. Войти как `engineer`, создать новую учётную запись.
2. Войти как `operator`, добавить адресата, создать оповещение, сменить статус `Created → Sent`.
3. Симулировать отправку по e-mail и добавить обращение, приложить HTTPS-ссылку на документ.
4. Войти как `manager` и показать полную карточку с аудитом.
5. Войти как `observer` и убедиться, что доступны только собственные записи без журнала аудита.
6. Как `operator` списать адресата и убедиться, что новые оповещения ему выписать нельзя, а старые сохранены.
7. Выполнить API и SQL smoke-проверки.
