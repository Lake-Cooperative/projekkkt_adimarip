# Журнал решений и открытые вопросы

Решения команды по вопросам, в которых бизнес-требования (БТ), варианты использования (UC) и ТЗ молчали или
противоречили друг другу. Состояние — на 20.11.2026 (выпуск №70). На эти номера ссылаются
[`system_requirements.md`](system_requirements.md) и [`ROADMAP_PRERELEASE.md`](ROADMAP_PRERELEASE.md).

## Принятые решения

| № | Вопрос | Решение | Где в коде |
|---|---|---|---|
| 1 | Кто видит историю и аудит (БТ §4.10 и UC-09 — управитель; UC §4 — «аудит» в карточке для всех) | История — при праве `HistoryView` (секретарь, управитель), аудит — при `AuditView` (управитель). Остальным `history = []`, `audit = null`. | `NoticeDetailMapper` |
| 2 | Документы и служащий (БТ §3.3 разрешает подачу документов, UC §6 запрещает изменения) | Служащий может только добавлять ссылки на документы и только к своим оповещениям; остальные изменения ему закрыты. | `DocumentService` |
| 3 | Маршруты входа и учётных записей не описаны в UC | `POST /api/auth/login`; учётные записи — `/api/admin/users` (право `UsersManage`). | `AuthEndpoints`, `AdminEndpoints` |
| 4 | Статусы оповещения и переходы не определены | 7 статусов и конечный автомат: `Created→Sent/Cancelled`, `Sent→Delivered/Failed/Cancelled`, `Failed→Sent/Cancelled`, `Delivered→Read/Closed`, `Read→Closed`. Повтор и прочие переходы — 409. | `NoticeLifecycle` |
| 5 | Состав подразделений | Фиксированный список из начальных данных; редактирования через API нет. | `DemoDataTask` |
| 6 | Обязательные поля адресата и оповещения | Адресат: идентификатор, ФИО, дата рождения; оповещение: номер, адресат, подразделение, срок, причина. Комментарий, контакты и адрес — необязательны. | `Recipient.Create`, `Notice.Register` |
| 7 | Типы обращений | Свободная строка до 100 символов (пример — `Clarification`); обработка обращений вне объёма. | `Notice.FileAppeal` |
| 8 | Доступ инженера к реестру | Нет доступа к бизнес-данным; виден только справочник подразделений (для привязки работников). | `SystemRoles` |
| 9 | Автор оповещения: из запроса (UC §4) или из JWT | Из JWT — подменить автора нельзя. | `NoticeService.CreateAsync` |
| 10 | Код ответа на дубликат адресата | 409. | `DirectoryService` |
| 11 | Реальная отправка уведомлений | Не реализуется: доставка имитируется в демо-режиме, вне демо — 501. Архитектура готова к подключению провайдера (`IChannelSender`). | `NotificationGateway` |
| 12 | Кто создаёт адресатов (БТ, UC-01 — секретарь) | Инженер (право `RecipientsCreate`), вместе с учётной записью работника — так ID адресата и работника совпадают. Кастомной роли право можно выдать. | `UserAdminService` |
| 13 | Формат ошибок (ТЗ §4.1.8 — `application/problem+json`) | Единое тело `{ "error": "..." }` на русском для всех маршрутов — проще для интерфейса. | `ResultHttpExtensions` |
| 14 | Фиксированные роли или настраиваемые (требование корпорации) | Права (17) + роли как наборы прав; четыре исходные роли — системные и неизменяемые. | `Domain/Access` |
| 15 | Как оповещать работников массово и быстро (требование корпорации) | Фоновая приоритетная очередь, параллельная доставка, резервный канал «Портал», для срочных — все каналы; отдельное оповещение реестра каждому работнику. | `BroadcastService`, `BroadcastDispatcher` |
| 16 | Как работник подтверждает получение | Отдельное действие «Ознакомлен(а)»: статус доводится до `Read` по разрешённым переходам, событие `Acknowledged` в аудите. | `Notice.Acknowledge` |
| 17 | Аудитория «по подразделению»: у адресата не было подразделения | Добавлено поле `Recipients.OfficeId` (миграция `202611190006`). | `Recipient.OfficeId` |
| 18 | Неизвестный статус в фильтре реестра | Пустой список (как фильтр без совпадений); в смене статуса — 400. | `NoticeService` |

## Открытые вопросы

| № | Вопрос | Что нужно для решения |
|---|---|---|
| О-1 | Подключение реальных провайдеров SMS/e-mail/MAX | Договоры с провайдерами, хранение ключей, учёт стоимости и лимитов; реализации `IChannelSender` |
| О-2 | Работа с реальными персональными данными (152-ФЗ) | Модель угроз, аудит безопасности, юридическое согласование |
| О-3 | Несколько экземпляров API | Очередь рассылок сейчас в памяти процесса; для нескольких экземпляров нужен внешний брокер или блокировка в БД |
| О-4 | Внешние ключи для авторов действий | `AuthorUserId`, `ChangedByUserId`, `UserId` — строки без FK на `AppUsers`; нужно решение, что делать при удалении учётной записи |
| О-5 | Обработка обращений | Статусы и ответственные за обращения не определены (сейчас только `Submitted`) |
