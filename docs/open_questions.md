## 1. Открытые вопросы интрокомандного обсуждения

Здесь собраны места, где были приведены соглашения меж разработчиками временно. Пока их нет в таблице решений, реализация идёт по значению из колонки «Временное решение».

| №   | Вопрос                                                                                                                                                                                         | Временное решение                                                                             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 1   | **Кто видит историю и аудит.** БТ §4.10 и UC-09 отдают их Управителю, но `GET /api/notices/{id}` доступен трём ролям и по UC §4 возвращает «аудит» всем.                                       | Поля `statusHistory` и `audit` возвращаются только Manager; для остальных ролей опускаются.   |
| 2   | **Документы и Observer.** БТ §3.3 и таблица UC позволяют Observer «подавать документы», а UC §6 говорит, что Observer не может изменять данные (403). Endpoint добавления документа не описан. | Observer может только `POST` документа; остальные изменяющие операции для него закрыты.       |
| 3   | **Endpoint входа и учётных записей** не описаны в UC (в UC-00 нет строки «API», в UC-11 написано «служебная функция»).                                                                         | `POST /api/auth/login`; создание учётных записей — `POST /api/users` для Automation Engineer. |
| 4   | **Статусы оповещения** и допустимые переходы **ПОКА** не определены. Известны только `Delivered` (доставка) и `Submitted` (обращение).                                                         | Список статусов задаётся конфигурацией; любой переход, кроме повтора текущего, разрешён.      |
| 5   | **Подразделения:** состав и правила ведения.                                                                                                                                                   | Фиксированный список из начальных данных US.                                                  |
| 6   | **Обязательные поля** адресата и оповещения.                                                                                                                                                   | Обязательны поля, перечисленные в SR-REC-02 и SR-NTC-05, кроме комментария и квартиры.        |
| 7   | **Типы обращений** и правила обработки.                                                                                                                                                        | Свободная строка типа; пример — `Clarification`.                                              |
| 8   | **Права Automation Engineer** на чтение реестра.                                                                                                                                               | Доступа к бизнес-данным нет.                                                                  |
| 9   | **Автор оповещения** передаётся в запросе (UC §4) и одновременно известен из JWT.                                                                                                              | Берётся из JWT (SR-NTC-09).                                                                   |
| 10  | **Дублирование адресата:** код ответа в UC не указан.                                                                                                                                          | **409**.                                                                                      |
| 11  | **Реальная отправка уведомлений** за пределами демо.                                                                                                                                           | Не реализуется.                                                                               |
