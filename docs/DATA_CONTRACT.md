# Решения по данным и статусам — учебная реализация

- `Recipient`, `Office`, `Notice`, `NoticeStatusHistory`, `AuditEvent`, `Notification`, `DeliveryAttempt`, `Appeal`, `Document` используют исходные EF-сущности проекта.
- `AppUsers` создаётся при старте SQL-командой с уникальным `Username`, ограничением перечня ролей и внешним ключом на адресата. Пароли — только PBKDF2-хеши.
- Служащий (`Observer`) имеет обязательную привязку к `RecipientId`. Неадминистративные роли не могут создавать учётные записи.
- Начальный статус — `Created`. Допустимые переходы задаёт сервер, а не интерфейс.
- При создании записи сразу фиксируются начальная история и аудит. Статус и журнал сохраняются одной операцией `SaveChanges`.
- Уведомления демонстрационные. Статус попытки `Delivered` означает **симуляцию**, не подтверждение доставки сторонним провайдером.
- Документы содержат только метаданные и ссылку, без загрузки бинарных данных.
- Публичные тестовые значения используются только на локальном учебном стенде.

**Совместимость:** изменения предназначены для миграционно-управляемой PostgreSQL. Если таблицы ранее созданы вручную или через `EnsureCreated`, используйте отдельную чистую демонстрационную БД после резервной копии.
