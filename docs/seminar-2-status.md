# Чекпоинт 2 — состояние и критерии приёмки

## Было во входном архиве

- `docs/`: бизнес-требования, системные требования, Use Cases, ERD и ROADMAP.
- `adimarip-efcore/`: десять сущностей, DbContext и черновая миграция PostgreSQL.
- `docker_compose.yml`: схема сервисов (до добавления приложений сборка была невозможна).
- **Не было** `backend/`, `frontend/`, каталогов `.git` и свидетельств об уже выполненных Git-коммитах участников.

## Что составляет семинар 2

1. ASP.NET Core 8 API: единственный бизнес-доступный endpoint `GET /api/health` со статусом `ok`.
2. Главная страница React 18 / TypeScript / Vite, отображающая запланированные разделы без ложного впечатления, что CRUD работает.
3. Swagger доступен в Development; EF Core и PostgreSQL подключаются конфигурацией, но DB API и миграции не запускаются автоматически.
4. В Docker Compose используются UI :8080, API :8081 и внутренняя PostgreSQL 16.
5. Требования и ERD маркируют будущие возможности отдельно от реализованного.

## Следующие этапы (НЕ реализованы)

JWT, создание аккаунтов, ролевые политики, миграции и тестовые данные, реестр оповещений, операции адресатов, история и аудит, уведомления, обращения и документы.

## Минимальный критерий готовности

- `docker compose -f docker_compose.yml up --build` собирает три сервиса на машине с Docker и доступом к реестрам пакетов/образов.
- `curl http://localhost:8081/api/health` возвращает JSON с `status: ok`.
- `http://localhost:8080` отображает брендированную главную страницу и статус API.
- `http://localhost:8081/swagger` открывается при `ASPNETCORE_ENVIRONMENT=Development`.

В предоставленной среде сборка .NET и Docker могут быть недоступны; отдельно фиксировать, что проверено статически, а что требует запуска.
