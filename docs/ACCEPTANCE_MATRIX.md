# Контрольные проверки (этапы M2–M12)

Ожидаемые ответы API; большинство строк автоматизировано в `tests/api_acceptance.py` и модульных тестах.

| Сценарий | Ожидание |
|---|---|
| GET /api/health без JWT | 200, `status=ok` |
| GET /api/notices без JWT | 401 |
| Вход с верным паролем | 200, JWT и роль |
| Вход с неверным паролем | 401 |
| Engineer обращается к `/api/notices` | 403 |
| Observer создаёт оповещение | 403 |
| Observer читает своё оповещение | 200, без истории/аудита |
| Observer запрашивает чужое оповещение | 404 |
| Manager открывает карточку | 200, включая аудит |
| Operator открывает карточку | 200, включая историю, без аудита |
| POST /api/notices с пустой причиной | 400 |
| POST /api/notices с повторным номером | 409 |
| PATCH status на текущее значение или запрещённый переход | 409 |
| PATCH status с несуществующим статусом (в т.ч. число, например `1`) | 400 |
| Правильный переход статуса | Новая история и аудит |
| Канал уведомления вне разрешённого списка | 400 |
| Демонстрационная отправка | Запись с `simulated=true`, журнал попыток, внешней отправки нет |
| SMS на адрес e-mail | 201, уведомление `Failed` с причиной «Некорректный номер телефона» |
| Отправка при `DEMO_ENABLED=false` | 501 |
| Обращение с пустым текстом | 400 |
| POST /api/notices/{id}/documents с http/js URL | 400 |
| Списание адресата | Скрыт из справочника, история сохранена |
| Создание оповещения списанному адресату | 409 |
| Engineer создаёт учётную запись | 201, пароль хеширован |
| Engineer создаёт служащего | 201, в ответе ID созданного адресата |
| Имя логина уже есть | 409 |
| Фильтрация/пагинация | `items`, `total`, `page`, `pageSize`, `totalPages` |
| Применение SQL-миграций | Полный набор таблиц и индексов |
| Инженер создаёт кастомную роль | 201; повторный код — 409; неизвестное право — 400 |
| Изменение системной роли | 409 |
| Удаление роли, назначенной пользователям | 409 |
| Пользователь кастомной роли без `NoticesCreate` создаёт оповещение | 403 |
| Права роли отозваны | следующий запрос — 403 без повторного входа |
| Служащий запускает массовое оповещение | 403 |
| Массовое оповещение с неизвестным каналом / пустой аудиторией | 400 |
| Массовое оповещение | 202 сразу; в отчёте все адресаты обработаны, `pending = 0` |
| Работник подтверждает своё оповещение | 200, статус `Read`; повтор — 409; чужое — 404 |
| Отчёт рассылки после подтверждения | `acknowledged` увеличился |

Важно: проверяйте эти сценарии в запущенном Docker и не используйте реальные сведения о гражданах.
