# Изоляция получателей (Observer) — исправление №71–73

**Назначение:** получатель видит исключительно свои оповещения. Вход по логину и паролю не должен открывать данные других адресатов.

## Как определяется получатель

- `AppUsers.RecipientId` — привязка аккаунта `Observer` к единственному адресату.
- При выдаче JWT ID добавляется в подписанный токен.
- API при чтении перепроверяет и роль, и текущую привязку пользователя по `AppUsers`. Несовпадение, отсутствие привязки или неверная роль приводят к запрету доступа.
- `GET /api/recipients` возвращает только собственную карточку, `GET /api/notices` — только собственные оповещения, `GET /api/offices` — лишь подразделения в собственных оповещениях.
- Прямой запрос чужой карточки `GET /api/notices/{id}` отвечает `404`. Проверка и фильтрация выполняются **сервером**, а не только React.
- В интерфейсе Observer остаётся раздел «Мои оповещения»; общий справочник «Адресаты» скрыт.
- Operator/Manager продолжают выполнять предусмотренные ТЗ задачи. Engineer не получает доступ к реестру.

## Как проверить вручную

1. Создайте два разных адресата A и B и запомните их ID.
2. Под инженером создайте `Observer A` с `RecipientId = A`, затем `Observer B` с `RecipientId = B`. Не подставляйте ID наугад: это определяет, кому принадлежат уведомления.
3. Под оператором создайте оповещение для A и отдельное для B.
4. Войдите как Observer A: виден только список A; нет общего раздела адресатов. По прямому ID карточка B должна вернуть 404.
5. Повторите для Observer B, убедитесь, что виден только B и запрещена карточка A.
6. Для автоматической регрессии: `python3 tests/api_acceptance.py` после запуска стека с `DEMO_ENABLED=true`. Скрипт создаёт **тестовые** записи в БД.

Если в браузере всё ещё видны чужие данные: убедитесь, что в заголовке показана **роль Observer** (не Manager/Operator), что аккаунт привязан к правильному `RecipientId`, выйдите из старой сессии и обновите контейнеры командой `docker compose -f docker_compose.yml up -d --build`. Не проверяйте этот сценарий под оператором: его роль по ТЗ действительно показывает полный реестр.

## Замечание об эксплуатации

Это усиление изоляции записей, **не полная проверка безопасности** системы. Для реальных персональных данных необходимы отдельные тесты доступа, логи, аудит конфигурации и проверка развёртывания. Реальная отправка уведомлений не реализована.
