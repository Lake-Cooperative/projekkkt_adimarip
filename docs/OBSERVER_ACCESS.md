# Изоляция данных работника («только свои оповещения»)

**Назначение:** работник видит исключительно свои оповещения. Вход по логину и паролю не открывает данные других адресатов.

## Кого касается

С выпуска №70 изоляция определяется **правами**, а не названием роли: её получает любая роль, у которой есть
`NoticesReadOwn` и нет `NoticesReadAll` — системный «Служащий» (`Observer`) или кастомная роль. Такая роль требует
привязки учётной записи к адресату: при создании пользователя адресат заводится автоматически.

## Как это обеспечивается

- `AppUsers.RecipientId` — привязка учётной записи к единственному адресату.
- На каждом запросе роль, права и привязка читаются **из БД** (`AccessResolver`), а не из токена. Нет привязки — 403.
- Ограничение «только свои» применяется **в SQL-запросе** (`WHERE RecipientId = …`), до загрузки данных.
- `GET /api/notices` — только свои оповещения; `GET /api/notices/{id}` чужого — **404**; `GET /api/recipients` —
  только своя карточка; `GET /api/offices` — подразделения собственных оповещений.
- Подтверждение получения (`/acknowledge`) и добавление документа — только к своему оповещению (чужое — 404).
- В интерфейсе работнику доступен раздел «Мои оповещения» с баннером срочных оповещений; справочник адресатов скрыт.
- Секретарь и управитель видят полный реестр (по ТЗ). Инженер к реестру доступа не имеет.

## Как проверить вручную

1. Под инженером создайте двух служащих A и B («Учётные записи», роль «Служащий») и запомните выданные ID адресатов.
2. Под секретарём создайте оповещение для A и для B (или запустите массовое оповещение на обоих).
3. Войдите как A: видно только оповещение A; карточка B по прямому ID — 404; справочника адресатов нет.
4. Повторите для B.
5. Автоматически: `python3 tests/api_acceptance.py` на стенде с `DEMO_ENABLED=true` (создаёт **тестовые** записи).

Если в браузере видны чужие данные — проверьте, что в шапке указана роль со «своими» данными (не Секретарь/Управитель),
что учётная запись привязана к правильному адресату, и пересоберите контейнеры:
`docker compose -f docker_compose.yml up -d --build`.

## Замечание об эксплуатации

Это изоляция записей, **не полная проверка безопасности** системы. Для реальных персональных данных нужны отдельные
тесты доступа, журналирование, аудит конфигурации и проверка развёртывания.
