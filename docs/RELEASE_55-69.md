## Выполненные изменения

- Backend (kkkolonel): обязательная БД, production-конфигурация без demo-секретов;
  первичное создание инженерной учётной записи; запрет ложной «доставки» вне
  демо; строгая пагинация; readiness endpoint для PostgreSQL.
- Frontend / DevOps (MasterChief-96): тот же origin для `/api` при Docker/Vite,
  CSP-заголовки nginx, реакция на истечение JWT, сохранение введённых обращений,
  маркировка демонстрационной доставки, более понятные ошибки ответа API.
- Database / PM (mcwkrsk): версия миграции AppUsers, новая проверка SQL,
  руководство по миграциям, HTTPS deployment через Caddy, GitHub Actions CI,
  сценарии резервного копирования и восстановления в тестовую БД.

## Что сознательно НЕ названо готовым

- Соединение с Госуслугами, MAX, почтой и SMS для настоящих уведомлений.
- Защита/сертификация системы для реальных персональных данных.
- Полная актуализация EF snapshot и управляемое промышленное обновление схемы.
- Реальный успешный прогон `dotnet build`, Docker и CI: это необходимо подтвердить
  на компьютере команды и в GitHub Actions после добавления коммитов.

## Порядок ручной отправки

Копировать папки **по очереди**, 55 → 56 → ... → 69; одну папку = один коммит.
Работать из актуальной ветки репозитория. После каждого push следующий участник
выполняет `git pull --ff-only`. Под каждым коммитом будет GitHub-автор именно того,
кто на своём устройстве выполнит `git commit` и `git push`.

## Проверка после объединения

1. `docker compose -f docker_compose.yml up -d --build` (только вымышленные данные).
2. `curl -f http://localhost:8081/api/ready` (готовность БД).
3. `python3 tests/api_acceptance.py` (при совпадающем `DEMO_PASSWORD`).
4. `npm run build` из `frontend`, `dotnet build backend/Adimarip.Api/Adimarip.Api.csproj`.
5. GitHub Actions: дождаться зелёного workflow (до него проверки не подтверждены).
6. HTTPS-профиль отдельно: `docs/PRODUCTION_DEPLOYMENT.md`.

### Отдельные ограничения среды подготовки архива

При изготовлении пакета не были доступны .NET SDK и Docker. Поэтому доступна
только проверка формы файлов и локальной последовательности Git-коммитов.
Сборку и интеграционные испытания должен выполнить runner GitHub Actions или
машина вашей команды.
