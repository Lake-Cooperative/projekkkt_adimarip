# Размещение на облачном хостинге (netrun, Railway, Render и похожие)

Такие хостинги собирают **один контейнер** из корня репозитория. Для них в корне лежит `Dockerfile`:
он собирает интерфейс (React) в статику и кладёт её в API, поэтому интерфейс и API работают на одном адресе.
База данных — отдельный сервис PostgreSQL на том же хостинге.

> Если сборка падает с `MSB1003: Specify a project or solution file`, хостинг собирает автосборкой Nixpacks
> без наших настроек. Проверьте, что в **ветке, которую деплоит хостинг**, в корне есть `Dockerfile` и
> `nixpacks.toml` (изменения нужно запушить). `nixpacks.toml` задаёт .NET 8, путь к проекту, сборку интерфейса
> и команду запуска, поэтому сборка работает и через Nixpacks, и через Dockerfile.

## Шаги

1. Создайте сервис **PostgreSQL** (версия 16 или новее).
2. Создайте сервис приложения из репозитория: сборка — `Dockerfile`, порт — тот, что хостинг передаёт в `PORT`
   (приложение слушает его само; по умолчанию 8080).
3. Задайте переменные окружения сервиса приложения:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Строка подключения от сервиса PostgreSQL вида `postgres://user:password@host:port/db` (или `ConnectionStrings__Default` в формате Npgsql) |
| `Jwt__Key` | Случайная строка не короче 32 символов |
| `ASPNETCORE_ENVIRONMENT` | `Staging` — для демонстрации (см. ниже); `Production` — без демо-режима |
| `Demo__Enabled` | `true` — демо-данные и имитация доставки (рассылки работают); `false` — для «боевого» профиля |
| `Demo__Password` | Пароль демо-аккаунтов, не короче 10 символов |
| `Bootstrap__Username`, `Bootstrap__Password` | Только без демо-режима: первый инженер (пароль 16–128 символов) |

4. Задеплойте. Миграции БД применятся при старте. Проверка: `https://<адрес>/api/ready` → `{"status":"ready"}`,
   затем откройте `https://<адрес>/` и войдите (`operator`, `manager`, `observer`, `engineer`, `duty`).

## Демо или «боевой» режим

В `Production` демо-режим запрещён защитой `ProductionSafetyGuard`, а без него уведомления и массовое оповещение
отвечают `501` (реальной доставки нет). Поэтому для показа на защите используйте `ASPNETCORE_ENVIRONMENT=Staging`
и `Demo__Enabled=true`. Данные вымышленные; не используйте такой стенд для реальных людей.

## Ограничения

* Запускайте **один экземпляр** приложения: очередь рассылок хранится в памяти процесса.
* Если хостинг «усыпляет» сервис без запросов, незавершённая рассылка продолжится после пробуждения.
* Полноценный вариант на своём сервере (HTTPS через Caddy, отдельные контейнеры) — [`PRODUCTION_DEPLOYMENT.md`](PRODUCTION_DEPLOYMENT.md).
